# 06 · 发布与分发

主题做好后有三种方式到达用户。本地导入和链接导入你自己就能完成；主题商店需要 NoraMusic 后台管理员操作。

## 方式一：本地文件导入（开发者自测 / 私下分享）

1. `python3 tools/pack.py my-theme` 得到 `dist/my-theme-1.0.0.noratheme`。
2. 把文件传到手机。
3. 打开 NoraMusic → **设置 → 主题 → 本地导入**，选择文件安装。

- 本地导入走与商店完全相同的静态校验，校验失败会提示具体原因。
- 本地导入的主题不走商店授权校验，离线可用。
- 适合开发期反复自测，或把主题直接发给朋友。

## 方式二：HTTPS 链接导入

把 `.noratheme` 放到任意公网静态托管（对象存储 CDN、GitHub Release 附件等），把 URL 发给用户，用户在 **设置 → 主题 → 链接导入** 粘贴即可。

链接的硬性限制（任一不满足即拒绝）：

| 限制 | 值 |
| --- | --- |
| 协议 | 仅 `https`（`http` 不行） |
| 端口 | 必须是 **443**（URL 不显式写端口即默认 443，可以通过） |
| 重定向 | 最多 **3 次**，且每次跳转目标都要重新满足全部限制 |
| 大小 | ≤ **128 MiB**（响应头 `Content-Length` 超限或实际下载超限都会中断） |
| 目标地址 | 必须是公网 IP；回环、内网、链路本地、多播地址均被拒绝 |
| 其他 | 不能带用户信息（`user:pass@`）、不能带 `#fragment`；连接超时 8 秒，整体超时 30 秒；证书无效会被拒绝 |

> 实践提示：GitHub Release 的附件下载 URL 会经历一次跳转，在 3 次重定向预算内，可以正常使用。短链服务多层跳转容易超限，不建议。

## 方式三：主题商店

商店面向全部用户，流程为：

```text
作者打包 → 管理员上传（生成草稿）→ 管理员发布 → 客户端主题商店列出
        → 用户下载（校验大小和 SHA-256）→ 安装 → 定期向后台确认授权
```

1. **上传**：管理员在后台"主题库"点击"＋ 上传主题包"（接口 `POST /admin/v1/themes/uploads`，multipart 表单中仅一个名为 `file` 的文件）。
   - 后台按包格式规则完整校验，通过后计算 SHA-256，生成**草稿**版本。
   - 同一 `manifest.id` 再次上传会作为同一主题的新版本。
   - `id` + `version` 都相同时返回 **409 `THEME_VERSION_EXISTS`**——更新主题必须提升 `version`。
2. **发布**：管理员点"发布"（`POST /admin/v1/themes/{thm_id}/publish`）。没有审核环节，发布后立刻对用户可见。
3. **撤回**：`POST /admin/v1/themes/{thm_id}/withdraw`。撤回后，已安装该版本的用户在下一次授权确认失败时回退到默认主题。
4. **客户端获取**：先请求 `GET /api/v1/capabilities` 确认主题功能开启且支持 schema 2，再请求 `GET /api/v1/themes` 获取已发布主题列表（每个主题只列出当前发布版本）。下载后核对文件大小和 SHA-256，再走一遍与后台相同的静态校验，然后解压安装。

### 商店授权校验

- 客户端在**启动、切换主题、回到前台时，以及每 4 分钟**，向后台请求一次 `POST /api/v1/themes/validate-installed`。
- 后台离线策略为 `allow` 时，断网可以继续使用已安装主题。
- 主题被撤回或授权无法确认时，客户端**回退到内置主题 Nora Light**。
- 因此商店主题的可用性依赖后台可达；纯离线分发请用本地导入或链接导入。

### 商店预览色

主题列表里的色块取自 `theme.json` 的 `colors.canvas`、`colors.accent`、`colors.textPrimary` 三个键。即使其他都从简，这三个也建议写上，否则列表里显示的色块不是你的配色。

## 版本管理

- 版本号格式：`主.次.修订` 三段纯数字（每段 1–5 位），不能带 `-beta` 等后缀。
- **id + version 不可变**：同一 id 的同一版本一旦上传即不可覆盖。改任何内容（哪怕一个颜色）都要提升版本号重新打包上传。
- 建议遵循语义化版本的习惯：改配色细节升修订号（1.0.0 → 1.0.1），加新配置升次版本号（1.0.1 → 1.1.0），重做整体风格升主版本号。
- 客户端目前**没有自动更新**：新版本会作为另一个条目出现在商店，用户需要手动下载；旧版本在被管理员撤回前一直可下载可用。

## 安全与合规

发布（尤其是上架商店）之前，请逐项确认：

- [ ] **素材版权**：背景图、插画为原创或允许再分发（CC0 / CC-BY / 已购授权），不含专辑封面、动漫截图、品牌 logo 等第三方版权内容。
- [ ] **肖像权**：人像写真需取得权利人授权。未获授权的写真主题只适合自己本地使用，不要公开发布。
- [ ] **字体许可**：仅使用 OFL 等允许嵌入再分发的字体，署名写在 `manifest.json` 的 `license` 与 `description` 中（许可证 .txt 放不进包）。
- [ ] **license 字段**：如实填写主题配置本身的许可证，如 `"MIT"`；含 OFL 字体时用 `"MIT AND OFL-1.1"` 这类组合写法。
- [ ] **不含外部资源**：包内（含 JSON 任意字段）没有任何 URL——主题必须自包含，这是硬性校验，也是用户安全的一部分。
- [ ] **作者信息真实**：`author.name` 建议填写可追溯的作者名；`author.url` 不要写（含 `://` 会被拒）。

## 三种方式对比

| | 本地导入 | HTTPS 链接导入 | 主题商店 |
| --- | --- | --- | --- |
| 谁能操作 | 作者本人 | 作者本人 | 后台管理员 |
| 触达范围 | 单个设备 | 拿到链接的人 | 全部用户 |
| 授权校验 | 无 | 无 | 每 4 分钟重校验，失败回退内置主题 |
| 离线可用 | 是 | 是（安装后） | 离线策略 `allow` 时是 |
| 版本约束 | 无（同版本可重复安装） | 无 | id+version 不可变，重复上传 409 |
| 适用场景 | 开发自测、私下分享 | 小范围分发 | 正式发布 |
